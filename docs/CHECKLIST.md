The release archive is produced with `pnpm package` (`git archive HEAD`, see `scripts/package.mjs`). Every line of the original release brief (the "SHIP" brief, kept outside this repo) is listed with how it was done or why it does not apply. Commands are run from the repo root with a filled `.env`.

## §2 P1 Security

- [x] Env-only secrets — `rg -i "sk_live|sk_test|service_role|\bre_[A-Za-z0-9]{8,}|whsec_" src public api middleware.ts` → only the variable *name* `SUPABASE_SERVICE_ROLE_KEY` in `src/lib/server/env.ts`; `build.mjs` refuses to emit non-public keys into `env.js`.
- [x] Anon key only in the browser — `public/assets/js/env.js` is generated from the PUBLIC allow-list (`SITE_URL`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `TURNSTILE_SITE_KEY`, `SENTRY_DSN`, `COURSE_RELEASED`).
- [x] RLS on every table — `node scripts/rls-report.mjs`: profiles, submissions, submission_files, waitlist, email_templates, email_events, email_sends, activity_log all `rls=ENABLED`; members read own rows, admins via `public.is_admin()`; member writes go through `api/*` (service role). Unused `public.campaigns` is dropped.
- [x] `proofs` bucket private, signed URLs 10 min — bucket `public=false`; `storage.objects` policies: read own folder or admin, insert/delete only `<uid>/incoming/`; admin views use `createSignedUrl(path, 600)`.
- [x] Server-side session check on /account and /admin — `middleware.ts` (Vercel Edge): no valid HttpOnly cookie → `/account/*` 307 to `/login/?redirect=…`, `/admin/*` 404 (also for signed-in non-admins); `tests/security.spec.js`.
- [x] Password hashing by Supabase Auth — no password ever touches our code beyond forwarding to GoTrue (`api/auth/login.ts`, `signup.ts`).
- [x] Rate limit 5 / 15 min per IP+email on login, signup, reset, waitlist, proof, unsubscribe, and admin password-reset — `src/lib/server/ratelimit.ts` on Upstash/Vercel KV REST; in production the store is mandatory (`500 ratelimit_unconfigured`, fail closed), in-memory fallback only locally; client IP from `x-vercel-forwarded-for` / `x-real-ip`, then right-most public `x-forwarded-for` hop (`tests/unit/campaigns.test.mjs`); `tests/unit/validation.test.mjs` + the 429 test in `tests/security.spec.js`.
- [x] Cloudflare Turnstile invisible on signup, login, reset, waitlist — token minted in `supabase-client.js`, verified in `src/lib/server/turnstile.ts`; skipped only when `TURNSTILE_SECRET_KEY` is empty outside Vercel / `NODE_ENV=production` (`env.failClosed`).
- [x] zod on every API input — `src/lib/validation.ts` schemas for login, signup, reset, session, waitlist, proof, admin member action, admin decision (`reason` required on reject), campaigns (discriminated union on `action`), email test (id or unsaved spec); 400 with field path, no stack (`tests/security.spec.js`).
- [x] HTML-escape user text everywhere incl. emails — `src/lib/escape.ts`, `escapeHtml` in `site.js`/`admin-app.js`, `fill()` escapes merge fields in `src/lib/server/send-template.ts`; unit test `escapeHtml / fillTemplate`.
- [x] Server-side decisions and campaigns — `POST /api/admin/submission` and `POST /api/admin/campaigns` (+ `GET /api/cron/send-campaigns`) run with the service role; the browser policies "Admins update submissions" / "Admins manage email sends" were dropped in the fifth migration. Every email is one `email_events` row (unique per template × member × submission and per send × recipient), so nothing double-sends. Campaign mail carries a signed one-click unsubscribe (`GET /api/unsubscribe`, HMAC-SHA256 with the service-role key; `tests/unit/campaigns.test.mjs`).
- [x] Uploads PNG/JPG/WEBP only, 5 MB, 4 files, sharp re-encode, EXIF stripped, random names — `api/proof.ts`: magic-byte sniff, `PROOF_MAX_BYTES/FILES`, `sharp().rotate().resize(2400, inside).webp({ quality: 84 })` (re-encode drops EXIF), `<uid>/<submission>/<randomUUID>.webp` names.
- [x] API returns only needed fields — every handler builds its response object explicitly (`json({ ok, is_admin })`, member rows selected by column list).
- [x] Security headers — `vercel.json` (mirrored by the dev server): CSP with script hashes (`scripts/csp-hashes.mjs`, checked in `pnpm test`), HSTS `max-age=63072000; includeSubDomains; preload`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`, `X-Content-Type-Options: nosniff`. Nonces n/a for static HTML → hashes instead. `curl -I http://127.0.0.1:5051/` shows them all. `/assets` is `public, max-age=0, must-revalidate` (filenames are not hashed); `/fonts` is `public, max-age=31536000` without `immutable`.
- [x] HTTPS only — Vercel terminates TLS; HSTS preload; cookies `Secure` on HTTPS.
- [x] `pnpm audit` clean — `pnpm audit --prod`: "No known vulnerabilities found".
- [x] Secure cookies — `tf-session`: `HttpOnly; Secure; SameSite=Lax; Path=/` (`src/lib/server/session-cookie.ts`, unit test).

## §2 P2 Email & data

- [x] SPF, DKIM, DMARC for `support@talaria-flow.com` — `DEPLOY.md` §2.1–2.3 with the exact records (Resend DKIM + SPF on the `send.` return path, `_dmarc` starting at `p=none` with aggregate reports and a documented path to `quarantine` → `reject`, MX for replies to support@).
- [x] Webhook delivered/opened/clicked/bounced → `email_events` — `api/webhooks/resend.ts`, Svix signature verified (`src/lib/server/svix.ts`, unit-tested), events keyed by `template_id` tag, unique per `provider_id` + event, `email_sends.opened_count` incremented on `email.opened`.
- [x] Retention cron: proofs deleted 90 days after decision — `vercel.json` cron `03:20 UTC` → `api/cron/purge-proofs.ts` (CRON_SECRET) → `src/lib/server/purge.ts`; manual `pnpm purge:proofs -- --dry`.
- [x] Campaign scheduler — `vercel.json` cron `0 8 * * *` → `api/cron/send-campaigns.ts` (CRON_SECRET required on every Vercel deploy) → `src/lib/server/campaigns.ts` `processDueSends()` (claims each row before sending). Same-day sends: admin `run-due` (DEPLOY.md §6.3). Course unlock: `COURSE_RELEASED=1` (DEPLOY.md §6.4).
- [x] Transactional emails sent once — `api/proof.ts` creates the submission only after every file is stored (rolls back otherwise) and sends 03 itself; 04/05 are sent by `api/admin/submission.ts`. No edge functions and no database webhooks on `submissions`.
- [x] Nightly DB backup — `DEPLOY.md` §1.6: PITR on Pro, daily automatic backups on Free + scheduled `supabase db dump` cron.
- [x] Sentry on client and server — `public/assets/js/sentry.js` (envelope API, `window.onerror`/`unhandledrejection`) and `src/lib/server/sentry.ts` from `handle()` in `http.ts`; both off when `SENTRY_DSN` is empty.
